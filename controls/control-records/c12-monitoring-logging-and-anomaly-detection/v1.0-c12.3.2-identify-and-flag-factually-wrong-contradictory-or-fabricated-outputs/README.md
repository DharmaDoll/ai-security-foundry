# 誤った・矛盾した・作り上げた回答を見つけて印を付ける

AISVS Verification Level: 2

学習資料：[C12.3 入力と出力の変化](../../../learning/c12-monitoring-logging-and-anomaly-detection/v1.0-c12.3-model-data-and-performance-drift-detection.md)

## Upstream basis

AISVS `v1.0-C12.3.2`は、事実と違う、矛盾する、または作り上げられた
情報を含むモデル出力を、検知の仕組みが見つけて印を付けることを求める。
ここでの印は、例えば「調査が必要」という記録であり、検知器が真偽を
完全に証明したという意味ではない。

対応するAISVS Researchは、根拠との照合、事実確認、矛盾の検査などを
挙げ、既知の正答・誤答を使って見逃しと誤検知を測るよう提案する。検知結果
と元の回答を結ぶことも重視する。一方、正規要件は特定の製品・手法・
精度値、回答の自動遮断を指定していない。

## Interpretation

対象とするモデル出力を決め、事実的な主張が誤っている、回答内や確認済みの
情報と矛盾する、存在しない情報を作り上げていると疑われる場合に、
その出力へ調査可能な印を付ける。例えば社内規程の回答で、施行日を誤る、
同じ回答の前後で金額が食い違う、存在しない規程番号を挙げる場合である。

単に回答が流暢か、モデルが「自信があります」と言ったか、引用が表示
されているかだけでは判断しない。比較に使う規程や検索結果が古い・汚染
されている可能性もあるため、何と照合した結果かを分けて扱う。

## Security objective

もっともらしい誤情報が、そのまま利用者の判断や後続のAgent処理へ渡り、
問題が見えなくなることを減らす。検知結果は調査と改善の入口であり、
全ての誤りの発見や回答の正しさを保証しない。

## Applicability

モデルが事実、規程、数値、手順、引用などを含む出力を作り、それを人や
下流の処理が利用するシステムに適用する。RAGの回答、要約、業務上の判断を
支える説明、Agentが作る報告などを含む。用途に応じ、何を「正しい情報」
として照合できるかを定める。

### Non-applicability

モデル生成の出力がない処理には適用しない。純粋な創作だけを扱い、事実に
関する主張も後続の判断への利用もない範囲は対象外とできる。ただし同じ
機能が資料の要約や実在の事実も述べるなら、その経路を一緒に除外しない。

## Scope and assumptions

- 「事実と違う」は、用途に合う信頼できる資料や既知の正答と照合して
  判断する。比較材料がない主張は、直ちに「誤り」と断定せず、未確認と分ける。
- 「矛盾」は一つの回答内の食い違い、またはその時点で確認できる資料との
  食い違いを含み得る。資料の版と有効日が違うだけなら、適用条件を確認する。
- 「作り上げた」は、存在しない資料、記録、数値、引用などを、存在する
  ものとして示す場合を含む。単に引用がないことだけでは捏造と決めない。
- 検査する出力経路と、全件か一部の抽出かを明示する。一部しか検査しない
  構成では、未検査の回答も評価済みであると主張しない。
- 別のモデルを検知器に使う場合も、その判定を独立した真実の証明とは
  扱わない。言語、用途、資料の更新後に性能が変わり得る。

## Assets, actors, identities, and trust boundaries

守る対象は利用者の判断、後続の処理が受け取る情報、誤答を調べられること。
利用者、モデル、検索・資料の仕組み、出力を検査する処理、調査担当者が
関わる。攻撃者が資料を汚染する場合もあれば、攻撃がなくてもモデルが
誤った説明を作る場合もある。

主な境界は、モデルの出力から検知処理、照合用の資料から検知処理、検知
結果から調査・後続処理への受け渡しである。モデルの自己評価や信頼でき
ない資料を、そのまま事実の正本にしない。

## Required security properties

| ID | 必要な性質と確かめ方 |
|---|---|
| SP-1 | 対象の出力経路で、事実誤認・矛盾・捏造を疑う内容を検査し、該当する回答へ印を付けられる。 |
| SP-2 | 印が、実際に検査した回答と結び付き、どの問題を疑ったか調べられる。別の回答や旧版へ誤って付かない。 |
| SP-3 | 対象の用途・言語で既知の誤答と正しい回答を使って試し、見逃しと誤検知の限界を把握する。 |
| SP-4 | 検知器が使った資料・設定や検査できなかった回答を区別し、未検査や未確認を「正しい」と扱わない。 |

## Scope calibration and adjacent assurance

| 観測 | 本Controlでの扱い |
|---|---|
| 既知の誤った金額、回答内の矛盾、架空の規程番号を与えても印が付かない | Fail。求める種類の誤りを識別できていない。 |
| 誤答を見つけるが、印が別の回答へ付く | Fail。問題の出力を調べられない。 |
| 全回答に一律に印を付け、正しい回答と区別しない | 識別したとは言い難くFail。誤検知を確認する。 |
| 根拠資料に支持がないが、主張が外部では正しい可能性がある | 「この資料では裏付けられない」と「事実として誤り」を区別する。 |
| 誤答へ印は付くが、利用者にもその回答を返す | 本要件の検知と、公開前に止めるかどうかの判断は別。 |
| 検知結果を週ごとに集計していない | 本要件だけではFailとしない。割合の時系列はC12.3.3で確認する。 |

## Threat and failure-mode rationale

モデルの誤答や架空の引用は、自然な文章で提示されると見過ごされやすい。
資料が汚染された場合は、検知器も同じ誤情報を「根拠あり」と判定し得る。
検知器が単に点数を出すだけで元の回答へ印を付けなければ、調査や改善にも
つながらない。逆に検知器の誤判定を確定事実として扱うと、正しい回答まで
不当に疑う。外部の脅威IDとの厳密な対応付けはまだ評価していない。

## Verification

### Architecture and configuration review

どの出力経路をいつ検査するか、照合用の資料や正答例の出どころ、検知結果の
記録先、回答との結び付け、調査担当者が確認する方法を追う。RAG、要約、
多言語など用途ごとの検知能力と、検知器・資料の変更時の再評価を確認する。
一部の回答だけを検査する場合は、抽出方法と未検査分の扱いを明示する。

### Positive verification

実データを使わず、正答が分かる合成資料と質問・回答を用意する。誤った
日付や金額、回答内で食い違う条件、存在しない資料や引用をそれぞれ試す。
該当する回答へ印が付き、理由や照合先を調べられるか確かめる。同時に、
正しい回答や「分からない」と適切に述べた回答を試し、誤検知も測る。

### Negative and abuse-case verification

| ID | 試すこと | 期待する確認結果 |
|---|---|---|
| N-1 | 合成資料では10日と決まっている期限を、回答で30日と述べる | 事実誤認を疑う印が元の回答へ付く。SP-1、SP-2。 |
| N-2 | 同じ回答の前半と後半で、適用条件を逆に述べる | 矛盾を見つけて印を付ける。SP-1。 |
| N-3 | 存在しない規程番号や資料を実在するように挙げる | 作り上げた情報を疑う印が付く。SP-1。 |
| N-4 | 正しい回答と適切な不確実性の表明を与える | 一律に問題ありとせず、誤検知を把握する。SP-3。 |
| N-5 | 回答を並行して生成し、検知結果の対応IDを入れ替える | 別の回答へ印が移る不備を発見する。SP-2。 |
| N-6 | 照合用資料や検知器を更新・停止し、検査不能にする | 以前の判定を流用せず、未検査・未確認を明示する。SP-4。 |

### Failure conditions

対象の出力について、既知の事実誤認・矛盾・捏造を識別して印を付けられない、
印が元の回答へ結び付かない、または検査していない回答を問題なしとして
扱う場合はFail。全件を「問題あり」とするだけで正答との区別もできない
検知器も実効的とは言えない。特定製品、別モデル、普遍的な精度値、回答の
自動遮断がないことだけではFailとしない。

## Evidence expectations

| 証拠 | 作成元 | 対象 | 確認する時期 | 保護上の注意 | 合格の目安 |
|---|---|---|---|---|---|
| 検査の対象と照合方法 | アプリ・監視の担当者 | 出力経路、資料、検査器、結果の保存先 | モデル・資料・検査器の変更時 | 実際の機密回答を載せない | 何をどう比べ、検査不能をどう表すか説明できる。 |
| 合成した正答・誤答による試験 | 試験担当者 | N-1〜N-4、対象の用途・言語 | リリース時・大きな変更時 | 合成資料と架空の規程を使う | 三種類の誤りを検知し、正答の誤検知も測れる。 |
| 回答と印の対応・停止時の試験 | 監視・調査の担当者 | N-5、N-6、抽出した回答の範囲 | 検知経路や記録形式の変更時 | 閲覧権限と保存期間を限定する | 元の回答へ辿れ、未検査を正答と混同しない。 |

## Known limitations and uncertainty

正規要件は、検知の対象範囲や最低精度を数値で定めていない。全ての分野・
言語で信頼できる正答資料を用意することは難しい。資料の汚染、古い版、
検知器自体の誤りにより、見逃しや誤検知が起こる。一部だけ検査する場合は、
未検査の回答へ保証を広げられない。印が付いても利用者へ誤答が届く可能性は
残り、公開前の防止は別に設計する。`verifiable`は本書の成熟度であり、
実製品の適合結果ではない。
