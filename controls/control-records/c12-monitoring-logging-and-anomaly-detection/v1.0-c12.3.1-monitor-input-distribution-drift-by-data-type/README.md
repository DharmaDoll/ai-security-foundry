# 入力データの傾向の変化を、データの種類に合う方法で見つける

AISVS Verification Level: 1

学習資料：[C12.3 入力と出力の変化](../../../learning/c12-monitoring-logging-and-anomaly-detection/v1.0-c12.3-model-data-and-performance-drift-detection.md)

## Upstream basis

AISVS `v1.0-C12.3.1`は、モデルの性能に影響し得る入力の分布変化を、
データの種類に合う、統計的に妥当性を確かめた方法で監視することを求める。
**分布**は、例えば「どの種類の質問がどの割合で届くか」という全体の
傾向である。その傾向が以前と変わることを**ドリフト**という。

正規要件が例に挙げるKS検定・PSIは表形式の数値、埋め込みベクトル間の
距離は文章や画像のための候補であり、指定製品や唯一の合格方法ではない。
対応するAISVS Researchは、比較の基準となる期間、必要なデータ数、
対象を分けた評価、方法の変更履歴なども確認するよう提案する。これらの
具体的な設定値は、正規要件から一律には決まらない。

## Interpretation

モデルへ入るデータのうち、振る舞いや品質に影響し得る主な種類を決め、
以前の傾向と現在の傾向を継続して比べる。比較には、そのデータに意味の
ある方法を使い、実際に起こり得る変化を発見できるか試す。

例えば社内RAGで、質問件数は変わらなくても、一般的な事務手続きの質問が
減り、専門的な人事制度の質問が増えることがある。件数だけではこの変化を
見落とす。文章の種類を適切に表す指標で比べれば、調査のきっかけを作れる。
反対に、利用が増えただけで質問の傾向は同じかもしれない。

## Security objective

モデルが想定していた入力と実際に届く入力のずれを早く把握し、回答品質や
安全性の変化を調べる入口を作る。分布が変わっただけでは、攻撃、障害、
モデル性能の低下のどれかは決まらない。

## Applicability

入力の内容や構成の変化によってAI機能の性能が変わり得るシステムに適用する。
文章の質問、画像、音声、数値や分類項目など、実際に使う入力の種類に
合わせて対象を選ぶ。RAGでは、質問だけでなく、モデルへ渡す取得文書の
構成も性能に影響し得る場合は評価対象として検討する。

### Non-applicability

評価対象の処理に、比較可能なAI入力が存在しない場合は対象外とできる。
「数値の入力がない」ことは、文章や画像の入力まで対象外とする理由には
ならない。影響が小さい入力項目を除く場合は、その理由を明示する。

## Scope and assumptions

- 比較の基準は、いつ・どの入力から作ったかを明らかにする。**基準期間**
  とは、現在と比べるために選んだ過去のデータの期間である。
- 方法の妥当性は、対象のデータ型、必要なデータ数、変化の大きさを考慮して
  確かめる。数字が出るだけ、または有名な手法を使うだけでは足りない。
- 文章や画像を数値に変換する**埋め込み**を使う場合、変換器と前処理の
  版が変わると、同じ入力でも数値が変わり得る。入力の変化と混同しない。
- 利用者の集団や機能を分けて見る必要がある場合は、その単位を決める。
  全体では小さな変化でも、重要な一部に集中することがある。
- 入力内容を保管する場合は機密情報の取り扱いを別に定める。全文の長期
  保存は本要件の必須条件ではない。

## Assets, actors, identities, and trust boundaries

守る対象は、AIの判断や回答に頼る利用者、入力により変わり得る品質、
そして変化を調べるための観測結果。利用者や外部データの提供者、AIアプリ、
前処理、モデル、監視処理、調査担当者が関わる。攻撃者が一部の入力を操作
できる場合もあれば、正規の季節変動や製品変更で分布が変わる場合もある。

主な境界は、外部の入力からアプリ・前処理、前処理済み入力から比較処理、
比較結果から運用上の判断へ渡す地点である。統計結果を、入力の安全性や
モデル性能の証明として扱わない。

## Required security properties

| ID | 必要な性質と確かめ方 |
|---|---|
| SP-1 | 性能に影響し得る主な入力の分布を、基準と現在の期間で比較し、変化を継続して観測できる。 |
| SP-2 | 各入力の種類に意味のある統計的方法を選び、必要なデータ数や変化の大きさを考慮して妥当性を確かめている。 |
| SP-3 | 既知の分布変化を試験で与えると検知でき、どの入力・期間・比較条件で起きたかを辿れる。 |
| SP-4 | 基準集団、前処理、埋め込みの変換器などが変わったときは比較条件を区別し、見かけの変化を入力ドリフトと取り違えない。 |

## Scope calibration and adjacent assurance

| 観測 | 本Controlでの扱い |
|---|---|
| 入力件数だけを追い、質問内容の構成が大きく変わっても分からない | Fail。分布の変化を監視できない。 |
| 数値には数値の分布比較、文章には文章に適した比較を行い、既知の変化を見つける | Pass候補。方法が対象データで妥当かも試す。 |
| 文章の入力が主なのに、無関係な数値項目だけを監視する | Fail。性能に影響し得る主な入力を見ていない。 |
| 検査器を変更した直後の差を、入力が変わった結果と断定する | 比較条件を揃えられずFail候補。変換器の変更だけなら原因を分けて調べる。 |
| 分布の変化を見つけたが、回答品質が落ちたかは不明 | 本要件の検知としては成立し得る。品質の評価は別に行う。 |
| 季節的な質問増を検知した | 検知自体は適切。想定内かどうかの分類はC12.3.4で確認する。 |

## Threat and failure-mode rationale

攻撃者が特定の種類の入力を増やす、または外部文書の構成が変わると、
モデルが想定外の質問に多く応じることがある。正規の業務変化でも同じことが
起こる。全体件数や平均だけを見ていると、重要な利用者集団や話題だけに
起きた変化を見逃し得る。逆に統計的な差を直ちに攻撃と決めると、正規の
変化への対応を誤る。外部の脅威IDとの厳密な対応付けはまだ評価していない。

## Verification

### Architecture and configuration review

対象の入力経路、データの種類、前処理、比較する基準期間と現在期間、
選んだ統計的方法、必要なデータ数、検知結果の確認先を調べる。方法が
対象データの変化に反応する根拠と、基準・前処理・変換器が変わった際の
扱いを確認する。重要な集団や機能を全体集計だけで隠していないかも見る。
KS検定、PSI、埋め込み距離のいずれかを必須とはしない。

### Positive verification

対象システムで使う入力の種類ごとに、通常の比較用データと、内容の傾向を
意図的に変えた無害な合成データを用意する。例えば数値入力なら値の範囲、
文章なら質問の話題の割合を変える。入力件数を同じにしたまま、対象の
監視が変化を検知し、対象の期間・入力・比較方法を辿れるか確かめる。
重要な利用者集団に限った変化が問題となる設計では、その集団でも試す。

### Negative and abuse-case verification

| ID | 試すこと | 期待する確認結果 |
|---|---|---|
| N-1 | 件数は同じで、質問の話題や数値の範囲だけを変える | 分布変化を見つけられる。件数だけの監視では合格しない。SP-1、SP-3。 |
| N-2 | 主な文章入力を監視対象から外す | 対象漏れを発見し、SP-1を満たさない。 |
| N-3 | データの種類に合わない比較方法や、試験で変化を見逃す方法へ替える | 妥当性の欠落を検出する。SP-2、SP-3。 |
| N-4 | 入力は同じまま、埋め込み変換器や前処理だけを変更する | 比較条件の変更を識別し、入力の変化と断定しない。SP-4。 |
| N-5 | 重要な少数の利用者集団だけで入力を変える | その集団を評価対象とした設計なら、全体平均に隠れない。SP-1、SP-3。 |
| N-6 | 比較に使える入力が極端に少ない期間を作る | 根拠の弱い結果を確実な検知とせず、データ不足を示す。SP-2。 |

### Failure conditions

性能に影響し得る主な入力の分布を監視していない、入力の種類に合わない
方法を妥当性の確認なしに使う、既知の変化を見つけられない、または比較
条件の変更を入力の変化と取り違える場合はFail。特定の統計手法・製品が
ないことや、検知した変化が攻撃か判定できないことだけをFailとしない。

## Evidence expectations

| 証拠 | 作成元 | 対象 | 確認する時期 | 保護上の注意 | 合格の目安 |
|---|---|---|---|---|---|
| 監視対象と比較方法の説明 | AIアプリ・監視の担当者 | 主な入力の種類、基準期間、方法、比較条件 | 入力・前処理の変更時 | 実際の質問や個人情報を載せない | データ型に合う方法と、妥当性を確かめた根拠が分かる。 |
| 合成データによる検知試験 | 試験担当者 | N-1〜N-3、N-5、N-6 | リリース時・監視変更時 | 無害な合成入力を使う | 既知の変化を見つけ、データ不足や対象漏れも識別できる。 |
| 比較条件の変更試験 | 前処理・監視の担当者 | N-4、基準集団・変換器の版 | 基準・変換器の更新時 | 原文の長期保存を前提にしない | 条件変更を入力ドリフトと誤認しない。 |

## Known limitations and uncertainty

統計的に差があっても、実際の回答品質に影響するとは限らない。重要な少数の
入力だけの変化は、全体の比較で見逃すことがある。入力の意味を数値化する
方法にも限界があり、変換器の更新で値が変わり得る。季節性や製品変更で
生じた変化と攻撃由来の変化は、この検知結果だけでは区別できない。
`verifiable`は本書の成熟度であり、実製品の適合結果ではない。
