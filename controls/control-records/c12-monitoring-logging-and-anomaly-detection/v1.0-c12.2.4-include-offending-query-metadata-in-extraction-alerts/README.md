# 抽出の疑いを知らせる通知から問題の質問を辿れるようにする

AISVS Verification Level: 2

学習資料：[C12.2 検知と通知](../../../learning/c12-monitoring-logging-and-anomaly-detection/v1.0-c12.2-detection-and-alerting.md)

## Upstream basis

AISVS `v1.0-C12.2.4`は、抽出の疑いを知らせる通知に、問題となった質問の
関連情報を含め、調査に役立てられることを求める。ここでの「関連情報」
（メタデータ）は、どの質問かを識別し、いつ・どこで起きたかを辿るための
情報である。

対応するAISVS Researchは、AIの振る舞いを大量の質問で複製する「モデル抽出」
を主な例に、質問やその識別子、対象モデル、検知理由などを挙げる。一方、
正規要件の `extraction-alert` は抽出の種類を限定せず、必須の項目名や、
質問本文を通知へ直接載せることも指定していない。内部指示を引き出す試行の
検知はC12.2.3で別に扱うが、その結果が抽出の通知になるなら本要件の
調査可能性も評価する。

## Interpretation

抽出の疑いという通知を受けた担当者が、問題の質問を他の質問と取り違えず、
調査を始められるようにする。通知には、質問を特定できる識別情報と調査に
必要な文脈を含める。質問の本文や詳しい記録を別の保管先に置く場合も、
通知から必要な期間に辿れることを確かめる。

例えば「モデル抽出の疑い、今週の利用量が増加」という通知だけでは、
どの質問を調べればよいか分からない。質問の識別子、時刻、対象機能、
検知理由が通知から分かり、許可された担当者が関連する質問の記録を調べ
られれば、疑いの妥当性や影響を検討できる。項目の組み合わせはシステムに
合わせて決める。

## Security objective

抽出の疑いを、調べようのない通知で終わらせない。問題の質問を特定し、
正規の大量利用との違いや影響を調べる手がかりを残す。同時に、通知へ
質問本文を無制限に複製して新たな漏えい先を作らない。

## Applicability

モデルの振る舞い、内部指示、その他の保護対象を引き出す試行について、
抽出の疑いを知らせる通知を生成するAIシステムに適用する。一件の質問に
基づく通知にも、複数の質問をまとめて出す通知にも適用する。

### Non-applicability

抽出の疑いに関する通知が設計上存在しない機能では、通知内容を直接検証
できない。ただし「通知を作っていないからPass」とはしない。抽出の試行が
起こり得るなら、検知や通知の欠落を別の要件と合わせて評価し、本要件は
評価不能または対象外とする理由を明記する。

## Scope and assumptions

- 「問題の質問」は、検知の根拠となった個々の要求を指す。複数の質問を
  まとめた通知なら、その範囲に含まれる質問を辿れる必要がある。検知器が
  一件を特定できないなら、その限界を通知で明らかにする。
- 質問の識別子、時刻、主体、対象機能・モデル、検知理由などは有用な例。
  すべてを一律の必須項目とせず、どの情報があれば調査できるかを試す。
- 質問本文の全文を通知へ載せることは求めない。別の保管先への参照を使う
  場合は、実際に解決できることを確かめる。復元できないハッシュ値だけ
  では、質問を特定できるとは限らない。
- 通知の項目は、検知器や信頼できる処理の記録から作る。質問した本人の
  自己申告やAIが作った説明だけを、正しい主体・対象の証拠にしない。

## Assets, actors, identities, and trust boundaries

守る対象は、調査で質問へ辿れることと、質問に含まれる機密情報・個人情報。
質問者、AIアプリ、検知器、通知を組み立てる処理、記録の保管先、調査
担当者が関わる。

主な境界は、質問の受付から信頼できる要求記録への経路、検知結果と要求
記録から通知を作る地点、通知から保護された質問記録を開く地点である。
異なる利用者や組織の質問を同じ通知へ誤って結び付けない。

## Required security properties

| ID | 必要な性質と確かめ方 |
|---|---|
| SP-1 | 抽出の通知に、問題の質問または質問群を識別できる情報が含まれ、別の要求と取り違えない。 |
| SP-2 | 通知の情報から、許可された担当者が必要な期間に問題の質問と検知の文脈を調べられる。 |
| SP-3 | 通知の主体・対象・時刻などは、信頼できる要求や検知の記録と対応し、質問者の自己申告やAIの作文に置き換わらない。 |

## Scope calibration and adjacent assurance

| 観測 | 本Controlでの扱い |
|---|---|
| 通知名と組織全体の総数だけで、問題の質問を特定できない | Fail。通知が存在しても調査の入口にならない。 |
| 要求IDと時刻を持ち、保護された記録から質問と検知理由を確認できる | 参照が実際に解決できればPass候補。本文の直接添付は不要。 |
| ハッシュ値だけを載せ、照合する記録もなく、どの質問か分からない | Fail。見た目の識別子だけでは調査できない。 |
| 複数質問をまとめた通知で、対象期間と該当する質問群へ辿れる | 個々の質問を調べられればPass候補。一件に絞れない限界は明示する。 |
| 問題の質問は辿れるが、そもそもの抽出検知が誤っている | 本要件の通知内容と、検知ルールの精度を分けて評価する。 |
| 通知に質問全文があり、閲覧権限が広すぎる | 本要件の項目充足とは別に、機密性の問題として報告する。 |

## Threat and failure-mode rationale

攻撃者が大量の質問を使ってAIの振る舞いを写し取ろうとする場合、通知に
合計数しかなければ、調査担当者は疑わしい質問と正規利用を見分けにくい。
内部指示を引き出す試行でも、対象の質問が分からなければ原因と影響を
調べられない。逆に、全ての質問本文を誰でも見られる通知基盤へ集めると、
調査のための仕組みが新たな情報漏えい経路になる。外部の脅威IDとの
厳密な対応付けはまだ評価していない。

## Verification

### Architecture and configuration review

抽出の通知を作る検知経路、要求IDの発行元、通知に載せる情報、質問記録の
保管先、保存期間、調査者の閲覧権限を確認する。複数質問をまとめる場合は、
集計結果から対象の質問群へ戻る方法を確認する。特定の監視製品、項目名、
スコア、質問全文の通知への添付は必須にしない。

### Positive verification

無害な合成質問を二人の利用者から別々に送り、一方の質問で抽出の通知を
発生させる。通知から正しい質問、時刻、対象、検知理由を調査でき、もう
一方の質問と取り違えないことを確かめる。複数質問に基づく通知なら、対象
の質問群を開いて確認する。本文を別に保管する構成では、許可された担当者
が参照を解決できることも試す。

### Negative and abuse-case verification

| ID | 試すこと | 期待する確認結果 |
|---|---|---|
| N-1 | 通知から要求IDや質問への参照を削る | 問題の質問を特定できず、本要件に合格しない。SP-1、SP-2。 |
| N-2 | 通知にはIDを残し、参照先の質問記録を削除・早期失効させる | 調査に必要な期間に辿れず、SP-2の証拠にならない。 |
| N-3 | 二人の質問を同時に送り、主体・対象の対応を入れ替える | 別人の質問へ誤って結び付く不備を発見する。SP-1、SP-3。 |
| N-4 | 複数質問をまとめて通知し、個々の質問との対応を捨てる | 対象の質問群へ戻れず、SP-1、SP-2を満たさない。 |
| N-5 | 質問本文に偽の利用者名や要求IDを書く | 自己申告を通知の正本にせず、信頼できる記録との対応を保つ。SP-3。 |
| N-6 | 許可のない役割で質問本文を開く | 通知内容の要件とは別に、記録の閲覧制限が働くか確認する。 |

### Failure conditions

抽出の通知はあるが、問題の質問を特定できない、通知の識別情報から記録へ
辿れない、または異なる質問を誤って指す場合はFail。通知の名前や総利用量
だけでは足りない。一方、特定の項目名、質問全文、検知スコア、監視製品が
ないことだけをFailとしない。検知の良し悪しや、通知を出すべき試行を
見逃したかは別の保証として確認する。

## Evidence expectations

| 証拠 | 作成元 | 対象 | 確認する時期 | 保護上の注意 | 合格の目安 |
|---|---|---|---|---|---|
| 通知と要求記録の設計 | AIアプリ・監視の担当者 | 質問ID、時刻、対象、参照先 | 通知形式や記録の変更時 | 実際の質問本文・秘密を載せない | どの情報を通知に含め、どこから取得するか説明できる。 |
| 合成質問による追跡試験 | 試験担当者 | N-1〜N-5、複数質問の集計 | リリース時・検知や通知の変更時 | 合成した無害な質問を使用 | 通知から正しい質問群と検知理由へ辿れる。 |
| 参照と閲覧の試験 | 記録・調査の担当者 | 参照先の保存期間、N-2、N-6 | 保存期間・権限の変更時 | 許可のない人には本文を見せない | 必要な期間に担当者が参照でき、閲覧制限も別途確認できる。 |

## Known limitations and uncertainty

正規要件は「抽出」の種類や必要な項目を細かく定義していない。Researchは
モデル抽出を中心に説明するが、それだけが対象と決め付けない。要求IDや
ハッシュ値で質問を指せても、参照先が消えれば調査できない。質問本文を
調べられても、攻撃の意図や成功を必ず判定できるわけではない。参照先を
長く残すほどプライバシーや保存費用との調整が必要になる。`verifiable`は
本書の成熟度であり、実製品が要件を満たす証拠ではない。
