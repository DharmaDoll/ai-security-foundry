# 誤答の疑いがある回答の割合を、時間を追って確認する

AISVS Verification Level: 2

学習資料：[C12.3 入力と出力の変化](../../../learning/c12-monitoring-logging-and-anomaly-detection/v1.0-c12.3-model-data-and-performance-drift-detection.md)

## Upstream basis

AISVS `v1.0-C12.3.3`は、事実誤認・矛盾・捏造などを含む回答の割合を
継続した時系列の指標として追い、傾向の分析と、悪化が続く状態の発見を
可能にすることを求める。**時系列**とは、同じ意味の数値を時刻や期間ごとに
並べたもの。単発の検知結果や、ある一週だけの数字とは異なる。

対応するAISVS Researchは、印が付いた回答数と検査した回答数、抽出方法、
検知器の版、比較対象の機能や言語を残すよう提案する。検知器や検査対象が
変わると、割合だけを並べても比較できないからである。特定の監視製品、
期間の長さ、警告のしきい値は正規要件で固定されていない。

## Interpretation

対象の回答について、各期間に「誤答の疑いあり」と判定された数を、
実際に検査された回答の数で割り、同じ定義で繰り返し記録する。例えば
100件を検査して5件に印が付けば、その期間の検知割合は5％である。
次の期間に100件中15件なら、見かけ上は15％へ上がったと分かる。

ただしこれは**検知器が疑わしいとした割合**であり、真の誤答率そのもの
ではない。検知器の版、検査した回答の選び方、質問の種類が変わったなら、
その変更を示して比較する。割合が高い状態が続くかを確認できるようにし、
上昇だけで「モデル本体が劣化した」と決め付けない。

## Security objective

一件ずつの誤答の疑いが散らばっていても、継続する悪化を見落とさない。
どの期間・用途で変化したかを調べ、原因の調査を始められるようにする。
この指標だけで攻撃、モデルの変更、資料の劣化などの原因は特定できない。

## Applicability

事実に関するモデル出力を継続して使い、誤答の疑いを検査・記録するAI機能に
適用する。全回答の検査でも、一部を抽出した検査でもよいが、抽出された
範囲の割合として表示する。RAG、要約、Agentの報告など、用途が異なる
回答を一つに混ぜる場合は、比較可能かを検討する。

### Non-applicability

モデル生成の事実的な出力がなく、C12.3.2の検査対象も存在しない処理は
対象外とできる。誤答の疑いをまだ検査していない機能は、割合が作れない
ことを理由に対象外とはしない。まずC12.3.2の検知・印付けの不足を示す。

## Scope and assumptions

- **分子**は、その期間に検査され「誤答の疑いあり」と判定された回答数。
  **分母**は、同じ期間・同じ対象範囲で実際に検査された回答数。未検査の
  回答を分母へ入れない。
- 何を一件の回答と数えるか、再生成や再試行を含むかを決める。分子と分母で
  集計単位が違う場合は割合として扱えない。
- 抽出検査では、選び方と検査した割合を明示する。高リスク回答だけを
  選んだ5％を、全回答の5％として表示しない。
- 分母が0なら割合は計算不能であり、0％としない。件数が少ない期間は
  数値が大きく揺れ得るため、件数と不確実さを併せて見る。
- 検知器の版、対象機能、言語、モデルや資料など、比較結果に影響する変更を
  追えるようにする。どの項目を分けて表示するかは製品の用途に合わせる。

## Assets, actors, identities, and trust boundaries

守る対象は回答品質の継続的な把握と、それを使う利用者・下流処理の判断。
モデル、誤答の検知器、集計処理、運用担当者が関わる。攻撃者が検索資料を
汚染することも、正規のモデル更新や質問の季節変動で数字が動くこともある。

主な境界は、個々の回答と検知結果から集計へ、集計から時系列の表示・判断
へ渡す地点である。検知器の判定を確定した正誤とみなさず、集計対象や
検知器が変わった時点を隠さない。

## Required security properties

| ID | 必要な性質と確かめ方 |
|---|---|
| SP-1 | 各期間の印付き回答数と検査済み回答数から割合を計算し、時刻付きで継続して追える。 |
| SP-2 | 分子・分母の対象範囲、抽出方法、集計単位が一致し、未検査・検査不能を正答として混ぜない。 |
| SP-3 | 検知器や対象集団の変更を区別し、比較できない数値を一つの傾向として見せない。 |
| SP-4 | 合成した継続的な割合の上昇を、設定した観察方法で発見し、対象期間と回答群を調べられる。 |

## Scope calibration and adjacent assurance

| 観測 | 本Controlでの扱い |
|---|---|
| 毎週の印付き件数だけを保存し、検査した回答数が分からない | Fail。割合を計算・比較できない。 |
| 一回だけ5％と算出し、その後の期間を記録しない | Fail。時系列や継続的な悪化を把握できない。 |
| 分母が0の週を0％と記録する | Fail。検査していないことと問題がないことを混同する。 |
| 抽出対象を全回答から高リスク回答だけに変え、同じ系列として15％を表示する | 比較条件の変更を隠しておりFail。別系列や再評価が必要。 |
| 同じ条件の複数期間で割合が上がり続け、担当者がその変化を把握できる | Pass候補。原因の断定は別の確認が必要。 |
| 検知器の誤判定が多く、割合も高い | 指標の限界として報告する。個々の検知精度はC12.3.2で別に確認する。 |

## Threat and failure-mode rationale

モデルや指示の変更、古い検索資料、汚染された入力などによって、誤答の疑い
が少しずつ増えても、一件ごとの記録だけでは持続的な悪化を見落としやすい。
反対に検知器を厳しくしただけでも印の割合は上がる。母集団が変わった場合も
同じである。割合の定義と比較条件を示さなければ、誤った原因へ対応して
しまう。外部の脅威IDとの厳密な対応付けはまだ評価していない。

## Verification

### Architecture and configuration review

回答、検知結果、時刻、集計の結び付けを追う。分子・分母の定義、未検査や
検査不能の扱い、抽出方法、期間の区切り、見せ方、継続的な上昇を発見する
方法を確認する。検知器の版、モデル、指示、検索資料、言語や用途など、
比較に影響する変更をどう残すかも確認する。特定の画面・警告方式・
しきい値は必須としない。

### Positive verification

合成回答を複数の期間に分けて投入する。例えば同じ対象範囲で100件ずつ
検査し、印付きが5件、10件、15件と増える試験を行う。時系列に5％、10％、
15％が正しく並び、上昇が継続したことを担当者が確認できるか試す。
各期間の件数と、必要な場合に元の回答へ辿れることも確認する。

### Negative and abuse-case verification

| ID | 試すこと | 期待する確認結果 |
|---|---|---|
| N-1 | 印付き5件のまま、検査済み回答を100件から20件に減らす | 件数は同じでも5％から25％へ変わる。SP-1、SP-2。 |
| N-2 | 未検査の回答を分母へ足す、または検査不能を正答として数える | 割合の過小評価を発見する。SP-2。 |
| N-3 | 分母が0の期間を作る | 計算不能と表示し、0％にしない。SP-1、SP-2。 |
| N-4 | 検知器の版や抽出対象を途中で変える | 比較条件の切替えを示し、無条件に同じ系列へ結ばない。SP-3。 |
| N-5 | 同じ条件で複数期間にわたる上昇を与える | 継続的な上昇を発見でき、対象期間と回答群を調べられる。SP-4。 |
| N-6 | 件数が極端に少ない期間や、一部の用途だけで上昇する期間を作る | 数値の不安定さや、重要な範囲が全体に隠れる可能性を示す。SP-2、SP-4。 |

### Failure conditions

印付き件数だけで割合を追えない、各期間の分母が不明、計算不能を0％として
扱う、比較条件の変更を隠す、または継続する上昇を発見できない場合はFail。
特定の期間幅や警告製品を使わないこと、上昇の原因がまだ分からないこと
だけではFailとしない。

## Evidence expectations

| 証拠 | 作成元 | 対象 | 確認する時期 | 保護上の注意 | 合格の目安 |
|---|---|---|---|---|---|
| 指標の定義 | AIアプリ・監視の担当者 | 分子、分母、抽出、期間、比較条件 | 検知器や対象範囲の変更時 | 実際の回答本文を載せない | 何の割合か、計算不能をどう扱うか説明できる。 |
| 複数期間の合成試験 | 試験担当者 | N-1〜N-3、N-5、N-6 | リリース時・集計変更時 | 無害な合成回答を使用 | 割合を再計算でき、継続する上昇を確認できる。 |
| 変更前後の比較試験 | 検知・監視の担当者 | N-4、検知器・抽出対象の変更 | 変更ごと | 利用状況の閲覧範囲を限定 | 比較条件が変わった期間を識別できる。 |

## Known limitations and uncertainty

検知器の見逃しや誤検知があれば、集計した割合にも誤差がある。一部だけ
検査する場合、対象の選び方が偏ると全体の実態を表さない。件数が少ない
期間では割合が大きく揺れ、普遍的なしきい値もない。割合が上がっても、
モデル本体、検索資料、指示、質問の構成、検知器のどれが原因かは分からない。
`verifiable`は本書の成熟度であり、実製品の適合結果ではない。
