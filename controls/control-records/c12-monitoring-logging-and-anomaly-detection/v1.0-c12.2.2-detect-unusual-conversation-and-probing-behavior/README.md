# 会話の流れや繰り返しから不自然な行動を見つける

AISVS Verification Level: 2

学習資料：[C12.2 検知と通知](../../../learning/c12-monitoring-logging-and-anomaly-detection/v1.0-c12.2-detection-and-alerting.md)

## Upstream basis

AISVS `v1.0-C12.2.2`は、行動の異常を調べる仕組みによって、普段と違う
会話の流れ、過剰な再試行、探り行動を見つけられることを求める。「探り行動」
とは、質問を少しずつ変えながらシステムの反応や制限を探すことを指す。

対応するAISVS Researchは、一件の質問では目立たない複数回の試行や、
利用者・会話ごとの時間的な変化を例に挙げる。Researchが示す分析方式、
製品、回数や時間のしきい値、検知精度の数値は、正規要件の必須条件ではない。
また、Researchは通知まで勧めているが、この要件本文が直接求めるのは
異常な行動を「見つける」ことである。

## Interpretation

一件ずつの入力だけでなく、同じ利用者や会話で起きた複数の操作を、順序と
時間を保って調べる。不自然な会話の変化、拒否後の繰り返し、少しずつ条件を
変える探索などを、調査できる結果として示す。回数の多さだけで悪意を確定
しない。

例えば、ある利用者が社内AIに内部指示を何度も聞き、断られるたびに言い方を
変える。一件ごとの文面は既知の攻撃表現に一致しなくても、会話全体を見ると
「同じ目的に向けた再試行」と分かる可能性がある。一方、業務で多くの文書を
調べる利用者は、質問が多いだけで攻撃者とは言えない。

## Security objective

単発の検査をすり抜ける継続的な試行を、運用者が気付ける形で示す。攻撃者の
意図を断定することではなく、調査すべき行動を見逃しにくくすることが目的。

## Applicability

利用者やエージェントが、AIとの会話、再試行、連続した要求を行える仕組みに
適用する。一回ごとに接続が切れるサービスでも、同じ主体が短時間に再試行や
探索を行えるなら対象として検討する。

### Non-applicability

AIとのやり取り自体がない機能には直接適用しない。画面に会話履歴がない、
匿名利用である、監視製品を使っていないというだけでは対象外にしない。
主体を安定して識別できない場合は、その制約を明示し、観測できる範囲で
評価する。

## Scope and assumptions

- 「普段と違う」は、同じ機能・利用者層で想定する使い方との比較を含む。
  一律の回数や時間だけで決まらない。比較方法は用途と運用に合わせて決める。
- 会話の順序、時刻、同じ主体・会話との対応が必要。本文をすべて保存する
  ことまでは要件に書かれていない。必要な情報と保存期間を分けて決める。
- 同じ利用者が会話を作り直しても追える設計は有効だが、要件は全ての
  匿名・複数アカウントの行動を結び付けることまでは指定していない。
- 検知結果は「疑い」を示す。認可や強い制裁を、判定結果だけに任せない。
  通知や対応への接続は重要だが、通知の必須条件はC12.2.1と区別する。

## Assets, actors, identities, and trust boundaries

守りたいものは、AIが持つ内部情報、利用可能な機能、利用資源と、継続した
攻撃を発見する能力である。利用者、エージェント、AIアプリ、行動の記録を
集める仕組み、異常を判定する仕組み、調査担当者が関わる。

境界は、各操作から行動の記録への経路、記録から複数操作をまとめる処理への
経路、判定結果から調査担当者への経路にある。利用者が入力欄に書いた名前や
AIが生成した利用者名だけで操作を束ねない。認証済みの利用者IDや信頼できる
会話IDを使える場合は、そちらを使う。

## Required security properties

| ID | 必要な性質と確かめ方 |
|---|---|
| SP-1 | 対象の操作について、順序・時刻・主体や会話との対応を保ち、複数回の行動として調べられる。 |
| SP-2 | 不自然な会話の変化、過剰な再試行、探り行動のうち対象システムで起こり得るものについて、用意した連続試験から異常を識別できる。 |
| SP-3 | 識別した結果から、対象の行動、判定理由、対象期間を確認でき、正規の高頻度利用と区別できるかを試せる。 |

## Scope calibration and adjacent assurance

| 観測 | 本Controlでの扱い |
|---|---|
| 一件ずつの危険な文面は検知するが、少しずつ変えた連続質問は見ない | Fail。C12.2.1とは観測の単位が違う。 |
| 要求回数だけを数え、同じ利用者の再試行や質問の変化を区別できない | 行動の異常を識別した証拠としては不十分。 |
| 拒否後に同じ目的の質問を言い換え続ける試験で、対象の一連の行動が示される | 本ControlのPass候補。検知しただけで攻撃阻止は証明しない。 |
| 正規の大量検索も全て攻撃と判定する | 誤検知が大きい。判定基準と用途に合わせて再評価する。 |
| 複数利用者が協調して攻撃するが、個別利用者の異常しか見えない | C12.2.3の個別ルール・横断検知も別に評価する。 |
| 異常な行動は見つけたが通知の配送先がない | 本要件の直接の「識別」は評価できる。運用上の通知・対応は別に確認する。 |

## Threat and failure-mode rationale

攻撃者は質問を小分けにし、拒否されても言い方を変えて試せる。単発の検知器は
各質問を無害と判定することがある。複数の操作をつなげられないと、この探索
を見落とす。一方、回数だけで判断すると、正規の活発な利用を誤って攻撃と
扱う。外部の脅威IDとの厳密な対応付けはまだ評価していない。

## Verification

### Architecture and configuration review

どの操作を記録し、何を使って同じ主体・会話の行動として束ね、どの期間を
見るかを確認する。拒否結果、質問の変化など、何を異常の手がかりにするか
確認する。別の会話へ移る場合の扱い、匿名利用の限界、保存期間、閲覧権限、
判定結果の確認方法も調べる。特定の統計手法やAI判定器は必須ではない。

### Positive verification

実データではなく、合成した会話で試す。例えば、通常の質問を続ける会話、
拒否後に同じ目的の質問を言い換える会話、短時間に条件を変えて制限を探る
会話を用意する。後二者が一連の行動として識別され、何に反応したかを確認
する。同じ回数の正規利用も流し、誤判定を測る。利用者を識別できる設計なら、
同じ利用者が新しい会話を始める場合も確認する。

### Negative and abuse-case verification

| ID | 試すこと | 期待する確認結果 |
|---|---|---|
| N-1 | 各質問は単発の攻撃検知に掛からないが、徐々に内部指示を探る会話を流す | 会話の変化として識別できる。SP-1、SP-2。 |
| N-2 | 拒否後に言い換えや再試行を短時間に繰り返す | 過剰な再試行として識別できる。SP-1〜SP-3。 |
| N-3 | 同じ回数だけ、正当な文書検索を行う | 回数だけで攻撃と断定せず、誤判定を測定できる。SP-3。 |
| N-4 | 同じ認証済み利用者が会話を作り直して試行を続ける | その利用者の行動をつなぐ設計なら、会話の切り替えで検知を失わない。SP-1、SP-2。 |
| N-5 | 質問本文に別の利用者名を書き込む | 自己申告した名前で別人の行動へ混入させない。SP-1。 |
| N-6 | 行動の記録を一部欠落・遅延させる | 判定の欠落や遅れを把握でき、完全に観測したかのように扱わない。 |

### Failure conditions

対象の複数操作を結び付けられない、適用範囲の不自然な会話・再試行・探り行動
の試験に反応しない、または判定結果から対象の行動を確認できない場合はFail。
単発の危険文面を見つける仕組みや、合計回数の表示だけでは足りない。一方、
特定のしきい値、機械学習方式、通知製品がないことだけでFailにしない。

## Evidence expectations

| 証拠 | 作成元 | 対象 | 確認する時期 | 保護上の注意 | 合格の目安 |
|---|---|---|---|---|---|
| 行動の記録と判定の設計 | AIアプリ・監視の担当者 | 主体、会話、時刻、拒否、質問の変化 | 機能や判定方法の変更時 | 個人情報や質問本文は必要最小限 | 複数操作をどう結び付け、何を異常とみるか説明できる。 |
| 合成した正常・異常の会話試験 | 試験担当者 | N-1〜N-5 | リリース時と判定方法更新時 | 実利用者の会話を使わない | 再試行・探り行動を識別し、正規利用との違いを測れる。 |
| 判定結果と記録欠落の確認 | 監視基盤の担当者 | 対象の行動、期間、N-6 | 連携や保存期間の変更時 | 調査できる人を限定する | 何に反応したか辿れ、観測できなかった範囲も分かる。 |

## Known limitations and uncertainty

「通常の行動」は利用者層や用途によって違う。試験で識別できても、未知の
手口や長期間・複数アカウントに分散した攻撃まで見つけられるとは限らない。
匿名利用では同じ人の行動を結び付けられない場合がある。質問内容を詳しく
記録すると調査には役立つが、プライバシー上の負担が増す。異常の判定は
誤り得るため、それだけで悪意や侵害の確証とはしない。`verifiable`は本書の
成熟度であり、実製品が要件を満たす証拠ではない。
