# 非信頼データ処理をツール呼出し能力から隔離する

AISVS Verification Level: 2

## Upstream basis

AISVS `v1.0-C9.3.5`を解釈する。要件本文は非信頼Dataを処理する構成要素をツール呼出し能力から隔離し、侵害されたData処理から未認可のツール呼出しが起きないことを求める。
採用済みstable v1.0の固定Revisionで本文と対応Researchの要件別検証・限界を確認した。
最新の版・製品への追従を意味しない。

Researchは権限を持たない読取側と実行側の分離、固定計画、型付きの受渡しを例示し、自由度とのTrade-offを補足する。
以下の具体例・Property・検証条件はRepository interpretationである。
Researchの製品、統計、事件、外部Framework Mappingを未検証のまま転記せず、
例示された実装方式を一律の適合条件にしない。

## Interpretation

Web・文書を読む処理が操作されても、それだけで強いツールを実行できない境界を作る。Processを分けただけで、戻り値の『実行せよ』を特権側が無条件に実行するなら隔離は実効的でない。

Web読取Componentは送信資格情報も送信APIへの自由な要求経路も持たない。抽出した宛先候補を返せても、送信側では独立したPolicyと信頼する依頼の範囲で判断する。

## Security objective

非信頼内容への接触がそのまま特権操作へ昇格することを抑える。

## Applicability

非信頼文書・Web・Tool Data等の処理と操作能力を組み合わせるAgent。

### Non-applicability

非信頼Dataに接しない、または操作能力がなく他の実行者を誘導する経路もない範囲は対象外とできる。Dataを内部保存しただけで信頼済みにはしない。

## Scope and assumptions

処理Component侵害を仮定し、資格情報・API・IPC・共有状態・戻り値から能力を追う。特定のDual-LLM製品等は必須でないが、Promptの約束だけは隔離ではない。

対象構成・採用Policy・許容する動作と評価境界を検証前に固定する。
不明な構成を安全と仮定せず、未確認範囲をEvidenceの不足として残す。

## Assets, actors, identities, and trust boundaries

資産は操作能力と制御情報。非信頼処理、結果受渡し、特権実行側を分ける。強制点は能力の非付与と、境界を渡る結果の用途制限・認可。

## Required security properties

Security Invariantは守るべき性質、Enforcement Pointはそれを実際に強制する場所を指す。

| ID | 必要な性質と観測条件 |
|---|---|
| SP-1 | 非信頼処理側から特権Toolを直接呼べない。 |
| SP-2 | 受渡しDataが無条件に制御命令・権限へ昇格しない。 |
| SP-3 | 共有File・Queue・資格情報等の迂回経路でも能力境界を保つ。 |

## Scope calibration and adjacent assurance

認可Middlewareだけで構造的隔離を示せるとは限らない。Schema適合も、自由Textが実行指示へ解釈されるなら十分でない。

## Threat and failure-mode rationale

攻撃者が文書内に送信・読取・削除の指示を埋め、読取Componentやその戻り値を通じて強い能力を利用する。

この保証の分析では外部脅威IDを付与する追加価値を確定していない。
攻撃者能力・失敗経路を具体化し、`threat_mappings`は空とする。
ResearchのMappingを自動採用せず、必要時に一次Sourceの固定版で別途評価する。

## Verification

### Architecture and configuration review

Dataと制御のFlow、資格情報、通信・IPC、共有状態、特権側の結果解釈を追う。

### Positive verification

非信頼文書から許可した事実を抽出し、予定した範囲の処理が成立することを確認する。

### Negative and abuse-case verification

許可された試験環境と模擬Dataを用いる。モデルが協力することに依存せず、
必要に応じて実行境界へ試験要求を直接与える。

| ID | 条件・操作 | 期待結果・対応Property |
|---|---|---|
| N-1 | 文書に未依頼の送信・削除指示を埋める | 指示だけで操作能力を使えない。SP-2 |
| N-2 | 侵害した読取Componentから直接Toolを呼ぶ | 資格情報・経路の制限で拒否。SP-1 |
| N-3 | 型に合う戻り値へ命令を混ぜる | 型適合だけで実行へ昇格しない。SP-2 |
| N-4 | 共有File・Queueを改変して実行要求を作る | 境界外の権限を得られない。SP-3 |

### Failure conditions

上表の期待結果に反する観測やSPの不成立は、本ControlのFailを裏付ける。
試験未実施、構成不明、結果を追跡できない場合はPassを裏付ける証拠不足であり、
実証された回避と区別する。隣接要件の不備だけで本Controlの意味を広げない。
