# 承認期限が切れた操作を実行させない

AISVS Verification Level: 2

## Upstream basis

AISVS `v1.0-C9.6.2`を解釈する。要件本文は定めた承認時間内に人の承認Gateが満たされない場合、待機中操作を阻止することを求める。
採用済みstable v1.0の固定Revisionで本文と対応Researchの要件別検証・限界を確認した。
最新の版・製品への追従を意味しない。

Researchは期限の正本、遅延承認、Queue・再試行・期限Race、無応答を許可に変える問題を補足する。
以下の具体例・Property・検証条件はRepository interpretationである。
Researchの製品、統計、事件、外部Framework Mappingを未検証のまま転記せず、
例示された実装方式を一律の適合条件にしない。

## Interpretation

承認待ちが長引いたことを、自動的に許可する理由にしない。期限を過ぎた元の要求は失効し、遅れて届いた承認や再送で復活しない。

期限内に応答がない送信要求は送らない。再申請を認める場合は新しい要求として確認し、古い承認を新しい要求へ流用しない。

## Security objective

承認者の不在・通知障害・通信遅延が高影響操作の自動許可に変わることを防ぐ。

## Applicability

期限付きの人の承認を待つAgent操作。

### Non-applicability

承認待ち操作が存在しない範囲は対象外。期限を未定義のままにすることは対象構成の適合理由にしない。

## Scope and assumptions

期限の起点・正本Clock・期限境界での受理順序を定める。人が端末で押した時刻とServerが承認を検証した時刻を混同しない。設定した意味で期限内承認が成立するか評価する。

対象構成・採用Policy・許容する動作と評価境界を検証前に固定する。
不明な構成を安全と仮定せず、未確認範囲をEvidenceの不足として残す。

## Assets, actors, identities, and trust boundaries

資産は待機操作と承認状態。人、承認Service、Timer、Queue、Executorを分ける。強制点は期限状態の確定と実行受付。

## Required security properties

Security Invariantは守るべき性質、Enforcement Pointはそれを実際に強制する場所を指す。

| ID | 必要な性質と観測条件 |
|---|---|
| SP-1 | 承認期限と成立条件が明示される。 |
| SP-2 | 期限内に有効承認がない操作は副作用前に止まる。 |
| SP-3 | 遅延・並列・再試行・再起動で期限切れを復活させない。 |

## Scope calibration and adjacent assurance

期限内の承認自体の正当性はC9.2.1、証票のReplay耐性はC9.2.8。永久待機は自動許可より安全でも、本要件の定義された期限処理の証明にはならない。

## Threat and failure-mode rationale

攻撃者が承認通知を遮断し、Timeout時のDefault Allowや遅延承認のRaceを使って実行する。

この保証の分析では外部脅威IDを付与する追加価値を確定していない。
攻撃者能力・失敗経路を具体化し、`threat_mappings`は空とする。
ResearchのMappingを自動採用せず、必要時に一次Sourceの固定版で別途評価する。

## Verification

### Architecture and configuration review

待機・承認・失効の状態遷移、Clock、Race、再申請、永続化、Queueを追う。

### Positive verification

期限内の承認だけで正常操作が実行され、期限切れの別要求は失効したままであることを確認する。

### Negative and abuse-case verification

許可された試験環境と模擬Dataを用いる。モデルが協力することに依存せず、
必要に応じて実行境界へ試験要求を直接与える。

| ID | 条件・操作 | 期待結果・対応Property |
|---|---|---|
| N-1 | 承認を送らず期限を超える | 実行せず失効・拒否。SP-1, SP-2 |
| N-2 | 期限後に承認を送る | 元要求を復活させない。SP-3 |
| N-3 | 期限処理と承認を同時実行 | 定義した順序で一貫して判断。期限切れの実行なし。SP-2, SP-3 |
| N-4 | 再起動・Queue再送・Clock異常 | 期限情報を失って自動許可しない。SP-1, SP-3 |

### Failure conditions

上表の期待結果に反する観測やSPの不成立は、本ControlのFailを裏付ける。
試験未実施、構成不明、結果を追跡できない場合はPassを裏付ける証拠不足であり、
実証された回避と区別する。隣接要件の不備だけで本Controlの意味を広げない。
