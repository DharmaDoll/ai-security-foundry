# ツール実行を最小権限で隔離する

AISVS Verification Level: 1

## Upstream basis

AISVS `v1.0-C9.3.1`を解釈する。要件本文は各Tool・Pluginを最小権限Sandboxで実行するか、モデル処理から別の方法で隔離することを求める。
採用済みstable v1.0の固定Revisionで本文と対応Researchの要件別検証・限界を確認した。
最新の版・製品への追従を意味しない。

ResearchはFile・Network・Processの実効到達性、Sandbox設定の迂回、API型ツールの権限制限を補足する。
以下の具体例・Property・検証条件はRepository interpretationである。
Researchの製品、統計、事件、外部Framework Mappingを未検証のまま転記せず、
例示された実装方式を一律の適合条件にしない。

## Interpretation

ツールが想定外の処理をしても、仕事に不要なHost、Data、他ツール、管理機能へ届かないようにする。Containerという名称だけで判断しない。

文書変換ツールは作業Directoryだけを読み書きし、Hostの秘密やRuntime管理Socketへ届かない。Sandboxが起動できないときに通常Processへ無言で切り替えない。

## Security objective

ツール侵害の被害を、許可された最小範囲へ閉じ込める。

## Applicability

Agentが使う実行型・API型ツールとPlugin。

### Non-applicability

ツール・Pluginを利用しない範囲は対象外。遠隔APIはProcess隔離の責任分界を示し、利用側の資格情報や到達先制限を残す。

## Scope and assumptions

ツールの必要能力と侵害時の想定能力を定義する。原文は特定VMや製品を必須にしない。設定上の隔離と実際の権限を照合する。

対象構成・採用Policy・許容する動作と評価境界を検証前に固定する。
不明な構成を安全と仮定せず、未確認範囲をEvidenceの不足として残す。

## Assets, actors, identities, and trust boundaries

資産はHost、秘密、他Workload。モデル処理、ツール実行、基盤管理を分ける。強制点はOS・仮想化・Network・資格情報等の実効境界。

## Required security properties

Security Invariantは守るべき性質、Enforcement Pointはそれを実際に強制する場所を指す。

| ID | 必要な性質と観測条件 |
|---|---|
| SP-1 | 各ツールの実行範囲・必要権限を特定できる。 |
| SP-2 | モデル処理や無関係な資源へ未許可の操作を行えない。 |
| SP-3 | 起動失敗・設定変更で強い隔離を弱い実行へ自動降格しない。 |

## Scope calibration and adjacent assurance

資源上限はC9.1.1、ツール引数の認可はC9.5.1。Sandbox内の許可操作が業務的に正当かは別。

## Threat and failure-mode rationale

悪意あるツールや入力が任意コードを実行し、共有Hostの資格情報・管理Socket・他Dataへ横展開する。

この保証の分析では外部脅威IDを付与する追加価値を確定していない。
攻撃者能力・失敗経路を具体化し、`threat_mappings`は空とする。
ResearchのMappingを自動採用せず、必要時に一次Sourceの固定版で別途評価する。

## Verification

### Architecture and configuration review

Mount、実効User、Capability、Network、秘密の配置、管理Socket、起動Option、Fallbackを調べる。

### Positive verification

必要なFileとAPIだけで正常な仕事を終え、不要な権限がなくても成立することを示す。

### Negative and abuse-case verification

許可された試験環境と模擬Dataを用いる。モデルが協力することに依存せず、
必要に応じて実行境界へ試験要求を直接与える。

| ID | 条件・操作 | 期待結果・対応Property |
|---|---|---|
| N-1 | 作業領域外の模擬Fileを読み書き | 拒否される。SP-1, SP-2 |
| N-2 | 未許可Host・管理Socketへ接続 | 到達・操作を拒否。SP-2 |
| N-3 | 特権起動Optionを要求 | 許可なく隔離を緩めない。SP-1, SP-3 |
| N-4 | Sandbox Backendを停止 | 無隔離Fallbackを起こさない。SP-3 |

### Failure conditions

上表の期待結果に反する観測やSPの不成立は、本ControlのFailを裏付ける。
試験未実施、構成不明、結果を追跡できない場合はPassを裏付ける証拠不足であり、
実証された回避と区別する。隣接要件の不備だけで本Controlの意味を広げない。

## Known limitations and uncertainty

隔離機構自身の脆弱性、Side-channel、許可先経由の漏えいが残る。未知のSandbox Escapeへの完全耐性は主張しない。

`verifiable`は本Artifactに解釈・脅威・検証・証拠期待値が揃った状態を表す。
製品試験の実施・製品適合・学習完了を意味しない。有限の試験で未知の攻撃を全て否定しない。
Engineering PatternとMappingは独立して評価し、その存在を本Controlの成熟条件にしない。
