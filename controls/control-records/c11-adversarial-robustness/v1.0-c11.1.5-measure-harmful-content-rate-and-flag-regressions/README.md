# 有害な出力の割合を自動測定し悪化を検知する

AISVS Verification Level: 3

[C11.1 Section講義](../../../learning/c11-adversarial-robustness/v1.0-c11.1-model-alignment-safety-and-robustness.md)

## Upstream basis

AISVS `v1.0-C11.1.5`は、自動評価器が有害な出力の割合を測り、定義された
しきい値を超える悪化に印を付けることを求める。**有害な出力の割合**は、
評価対象の出力のうち、定義した有害カテゴリに該当する出力の割合である。

対応するAISVS Researchは、試験Data、カテゴリ、判定器、分母の扱いが
変わると、Modelの振る舞いが同じでも数値が変わると注意する。比較可能な
基準値、評価器の確認、カテゴリ別の結果、意図的に悪化させた模擬試験を
勧める。一方、正規要件は特定の評価Tool、共通の数値しきい値、Releaseの
自動停止、人による全件判定までは指定していない。

## Interpretation

評価する出力の境界、有害カテゴリ、分子と分母、比較対象、悪化のしきい値を
先に定める。自動評価器が対象出力を判定して割合を計算し、比較対象より
悪化がしきい値を超えたときに、後から確認できる印や通知を出す。
実行ごとに試験Data、Model、評価器、判定基準の版を結び付け、比較条件が
変わっただけの見かけの増減と区別する。

例えば、同じ100件の合成質問で、承認済みModelの有害な回答が4件、候補Modelが
9件だったとする。割合は4%から9%へ5パーセンテージポイント悪化する。
事前に「3パーセンテージポイントを
超える悪化に印を付ける」と定めていれば、候補Modelには印が必要である。
候補だけ難しい質問を除いて分母を変えれば、この比較は成立しない。
この数値は説明用であり、AISVS共通のしきい値ではない。

## Security objective

Model、Prompt、安全性Filter、推論経路の変更で有害な出力が増えても、
手作業の印象や一部の成功例に頼らず、測定して発見できるようにする。
分母や判定器の変更で悪化が隠れることも防ぐ。検知は弱点の修正、
Releaseの停止、すべての有害出力の防止を意味しない。

## Applicability

文章、画像、音声などの内容を生成し、製品の方針で有害または禁止する
出力カテゴリを定めるModelと推論経路に適用する。自社Modelと外部Providerの
Modelを含む。Model単体の出力を測るのか、後段の安全性Filterを通った
利用者向け出力を測るのかを明示し、得られた結果をその境界の保証として扱う。

### Non-applicability

対象が内容を生成せず、有害な出力という評価対象が成立しない場合は、
Modelの能力と出力境界を示して対象外とできる。禁止カテゴリをまだ決めて
いないこと、自動評価器を持たないこと、外部Providerを使うことだけを
理由に対象外とはしない。測定できない出力形式は未評価として残す。

## Scope and assumptions

- **分子**は有害と判定された対象出力の件数、**分母**は定義した評価対象の
  出力件数とする。拒否、無応答、Error、再試行、一問から複数出力する場合を
  どう数えるかも事前に決める。
- **悪化**は、承認済みの比較基準と同じ意味の割合が増えることを指す。
  試験対象、カテゴリ、判定器が変わった場合は同条件で再計算するか、
  比較不能として扱い、旧基準を黙って使わない。
- **しきい値**は試験結果を見てから有利な値へ変えず、対象カテゴリと
  影響に応じて事前に定める。全体値だけでは重大だが少数のカテゴリの
  悪化が隠れ得るため、必要な区分も明示する。
- 自動評価器がModelを利用する場合、そのModelも誤判定し得る。
  既知の有害・無害な合成例で判定を確かめ、版や設定を記録する。
  特定の評価方式や固定の精度値を正規要件とはしない。
- 「印を付ける」は、定義した悪化が検出可能な状態になることを指す。
  通知、記録、Dashboard表示等の方法は選べるが、数値を保存するだけで
  悪化を識別できなければ足りない。

## Assets, actors, identities, and trust boundaries

守る対象は、利用者へ届く内容の安全性と、安全性の悪化を見つける能力である。
Model Provider、製品・安全性担当者、評価器の管理者、Release担当者が関わる。
攻撃者は入力を細工して有害な出力を誘発し得る。評価器自体も、誤判定や
試験Dataの偏りにより、実際の問題を見落とす可能性がある。

主な境界は、Modelまたは製品の出力から評価器へ、評価器の判定から割合の
集計へ、集計から悪化の印・通知へ進むところにある。出力Filterを通った
結果だけを測る場合、Model単体の有害出力率を証明したことにはならない。

## Required security properties

| ID | 必要な性質と確かめ方 |
|---|---|
| SP-1 | 有害カテゴリ、評価対象の出力境界、分子・分母、例外の数え方を事前に定義できる。 |
| SP-2 | 自動評価器が対象出力を判定し、件数と割合を再計算できる形で残す。 |
| SP-3 | 比較基準、試験Dataと判定器の版、悪化のしきい値を結び付け、同じ意味の割合を比較する。 |
| SP-4 | しきい値を超える模擬的な悪化で、測定対象と結果が分かる印・通知が実際に生じる。 |

## Scope calibration and adjacent assurance

| 観測 | 本Controlでの扱い |
|---|---|
| 比較可能な割合を自動測定し、定めたしきい値を超えた試験で印が出る | Pass候補。Modelが安全という意味ではない。 |
| 有害な出力を個別に遮断するが、割合を測らない | C7等の出力制御には寄与するが、本Controlは満たさない。 |
| 割合を出すだけで、悪化しても印が出ない | Fail。測定と悪化の検知は両方必要。 |
| 分母や判定基準を変えて旧結果と直接比較する | 比較不能。見かけの改善をPassにしない。 |
| 自動評価器が重大カテゴリの合成例を見落とす | 測定の意味が疑わしく、評価器の誤判定を確認するまでPassにしない。 |
| しきい値超過に印は出るが、Releaseは止まらない | 本要件だけでは直ちにFailとしない。Release判断と修正は別に評価する。 |
| 全体の割合は変わらないが、重大カテゴリが悪化する | 全体値だけの限界として報告し、製品Riskに応じたカテゴリ別判定を検討する。 |

## Threat and failure-mode rationale

安全性の変更後に少数の有害出力が増えても、代表例だけを人が見る運用では
見落としやすい。評価器が同じ出力を違う基準で判定したり、難しい入力を
分母から除いたりすれば、悪化が数値に現れない。逆に、比較条件だけが
変わると、実際には悪化していないのに印が出ることもある。
外部脅威IDとの厳密なMappingはまだ評価していない。

## Verification

### Architecture and configuration review

製品の禁止カテゴリ、Modelと出力境界、評価Data、評価器、集計方法、
比較基準、しきい値、印の保存・通知先を確認する。変更時にCorpus、
カテゴリ、評価器、Modelの版を追えるか調べる。全体値が重大カテゴリの
悪化を隠さないよう、どの区分を別に見るかも確認する。

### Positive verification

安全な合成例で、評価器が既知の有害・無害な出力を概ね意図どおり判定するか
確かめる。分子、分母、割合を独立に計算して、自動集計と照合する。
比較基準からしきい値を超えるよう合成結果を変え、対象の測定結果を
辿れる印が生成・保存・通知されるか確認する。しきい値以下では不要な
印が出ないかも見る。

### Negative and abuse-case verification

| ID | 試すこと | 期待する確認結果 |
|---|---|---|
| N-1 | 候補Modelだけ一部の難しい入力を除き、分母を小さくする | 比較条件の不一致を検出し、旧基準との直接比較を認めない。SP-1・SP-3。 |
| N-2 | 有害な合成出力を増やしてしきい値を超える | 自動割合が上がり、対象の印・通知が生じる。SP-2・SP-4。 |
| N-3 | 評価器のPromptや判定基準を変え、旧基準の割合と比べる | 判定器の版の違いを検出し、再評価または基準値の見直しを求める。SP-3。 |
| N-4 | 拒否・Error・再試行を実行ごとに違う方法で分母へ入れる | 数え方の不一致を発見し、割合の意味を揃える。SP-1・SP-3。 |
| N-5 | 集計は保存するが、悪化の判定処理を止める | しきい値超過でも印がないことを検出し、Failとする。SP-4。 |
| N-6 | 重大カテゴリだけ悪化させ、全体平均には埋もれさせる | 全体値の限界を示し、製品Riskに応じて区分別の基準を確認する。SP-1・SP-3。 |

### Failure conditions

自動評価器がない、有害な出力の割合を定義どおり計算できない、比較基準と
しきい値が定義されていない、またはしきい値超過でも印が出ない場合は
Passにしない。分母・カテゴリ・評価器の変更で比較不能な結果を、悪化なしの
証拠に使う場合もPassにしない。評価器が既知の有害例を系統的に見逃すなら、
測定として信頼できる範囲を示すまで証拠不足とする。

## Evidence expectations

| 証拠 | 作成元 | 対象 | 確認する時期 | 保護上の注意 | 合格の目安 |
|---|---|---|---|---|---|
| 測定定義 | 安全性・製品担当者 | カテゴリ、出力境界、分子・分母、比較基準、しきい値 | 測定導入・変更時 | 有害例の詳細や内部Policyを公開しない | 同じ意味の割合を再計算・比較できる。 |
| 評価器と試験Dataの記録 | 評価基盤の管理者 | 評価器の版・設定、合成例、試験対象 | 評価実施・変更時 | 実際の有害出力や顧客DataをRepositoryへ置かない | 既知例の判定と比較条件を追える。 |
| 割合と悪化の実行結果 | 自動評価器・集計基盤 | Model Version、件数、割合、しきい値、印の結果 | 各評価時 | 出力、通知、Logの機密性と改ざんを考慮する | しきい値を超える模擬悪化で印を確認できる。 |

## Known limitations and uncertainty

自動評価器の誤判定、試験Dataの偏り、Modelとの共通の盲点により、有害出力率を
過小・過大評価し得る。件数が少ない区分では偶然の変動が大きく、重大だが
まれな失敗が全体割合に埋もれる。Researchは人が判定したDataでの校正や
カテゴリ別しきい値を勧めるが、正規要件の一律の手順・数値ではない。
悪化を検知しても、修正やRelease停止が自動で保証されるわけではない。
`verifiable`は本書の成熟度であり、実製品の適合結果ではない。
