# C7.4 Source Attribution & Citation Integrity

対象はAISVS v1.0（採用済み安定版の固定Revision `78775233666a2022dcfb82037e5e029116955c00`）。

### v1.0-C7.4.1

AISVS Verification Level: 1

> Verify that responses generated using retrieval-augmented generation (RAG) include attribution to the source documents.

**意味を保った日本語訳:** 検索拡張生成（RAG）を使って生成したResponseに、元文書へのAttributionが含まれることを検証する。

### v1.0-C7.4.2

AISVS Verification Level: 1

> Verify that RAG attributions are derived from retrieval metadata and are not generated by the model, so provenance cannot be fabricated.

**意味を保った日本語訳:** 来歴が捏造されないよう、RAGのAttributionが検索Metadataに由来し、Modelによって生成されないことを検証する。

### v1.0-C7.4.3

AISVS Verification Level: 2

> Verify that claims in a RAG response can be traced to the retrieved chunk.

**意味を保った日本語訳:** RAG Responseの主張を、検索されたChunkまで追跡できることを検証する。

### v1.0-C7.4.4

AISVS Verification Level: 3

> Verify that generated media is watermarked to prove it was AI-generated.

**意味を保った日本語訳:** 生成Mediaに、AI生成であることを証明するためのWatermarkが付与されることを検証する。

[C7.4.2](../../control-records/c07-model-behavior-output-control-and-safety-assurance/v1.0-c7.4.2-derive-rag-attributions-from-retrieval-metadata/README.md)では、Modelが候補IDを選ぶ構成でも、出典表示の正本を今回のRetrieval Metadataに置くことを確認する。
[C7.4.3](../../control-records/c07-model-behavior-output-control-and-safety-assurance/v1.0-c7.4.3-trace-rag-claims-to-retrieved-chunks/README.md)では、個々の主張から取得Chunkの版と該当箇所へ辿り、単なる出典の存在と意味上の支持を区別する。
[C7.4.4](../../control-records/c07-model-behavior-output-control-and-safety-assurance/v1.0-c7.4.4-watermark-ai-generated-media/README.md)では、配布される生成MediaでWatermarkを検出できるかと、Watermarkだけでは証明できない事項を分ける。

C7.1は形式、C7.2は回答の信頼性、C7.3は出力の安全性、C7.4は出典の由来・主張の裏付けを扱う。ただし、これらは必ず順番どおり実装するPipelineではなく、同じ出力に重なる評価軸である。7.4.4はRAGの引用から外れ、生成Mediaの由来表示という別の枝に属する。

## 具体Scenarioと用語

社内規程を検索するRAGが「経費承認上限は100万円。出典：経費規程」と答える。経費規程は実在し、検索結果にも含まれるが、該当箇所は「10万円」と記す。Modelが出典名を捏造し得るほか、実在文書を引用しても、その主張が誤りである可能性がある。

- RAG：回答生成前に関連資料を検索してModelへ渡す構成。
- Retrieval Metadata：検索側が記録する文書ID、版、該当箇所等。Modelが作文した出典名とは区別する。
- Chunk：検索・表示の単位に分けた文書の一部分。
- Attribution：回答をどの資料へ結び付けるか。
- Claim support：引用箇所が、その回答中の個々の主張を本当に裏付けるか。
- Watermark：AI生成を識別するために生成Mediaへ付ける標識。特定Systemの発行者認証や内容の正確性とは別。

攻撃者は文書やMetadataの一部を書き換える、またはModelの回答へ影響する指示を注入することがある。Model自体も悪意なしに数値や出典を取り違える。Trust Boundaryは資料から検索Index、検索Metadataから出典表示、Model回答からUserの意思決定、生成Mediaから閲覧者の由来判断。

## 一本の線と別の枝

```text
RAG文書を検索
  → 検索Metadataから出典を構成【7.4.2】
  → 回答へ出典を示す【7.4.1】
  → 各主張と引用Chunkの対応を追う【7.4.3】

生成画像・音声等
  → AI生成を示すWatermark【7.4.4：別の枝】
```

Security Invariantは「Modelが出典の正本を作らない」「検索された文書と実際に示した引用箇所を追える」「出典が実在するだけで主張が正しいと推定しない」。Enforcement Pointは検索サービスのMetadata、アプリの引用組立て、回答公開前または評価時の主張とChunkの照合。主張の意味上の支持判定には不確実性が残るため、誤りの完全排除は主張しない。

具体設計では文書ID・版・Chunk IDを検索結果に持たせ、アプリが出典表示を構成する。Modelが生成した文書名を検索リストで照合するだけでは、出典の由来がModelでないことを保証しない。Metadata自体が信頼できるかも別途考える。

## Pass／FailとNegative tests

- Fail（7.4.2）：Modelへ本文だけを渡し、Modelが生成した「出典：経費規程」をそのまま表示する。
- 7.4.2をPassと評価できる構成例：出典表示が検索結果の文書ID・該当箇所のMetadataからアプリにより構成され、Modelに捏造できない。
- Fail（7.4.3）：出典文書が検索された事実だけを確認し、「100万円」という主張を「10万円」と記すChunkと照合しない。
- 7.4.4の限界：WatermarkでAI生成を示すことと、どの特定Systemが出したか、内容が真実か、改変されていないかは別。署名付き来歴Metadata等が提供する保証は方式・検証条件ごとに評価する。
- Negative test：存在しない出典、検索していない文書、実在するが数値が矛盾するChunkを提示し、由来と支持の異なる失敗を区別する。MediaではWatermarkの欠落・変換後の検出不能を試す。
- 正常系：正しく検索・引用した回答で、文書と該当箇所へ辿れる。生成Mediaで想定方式のWatermarkを検出できる。

## 設計演習：出典表示のDataを端から追う

以下はRepositoryによる追加教材であり、実製品の試験結果ではない。各試験の期待結果とEvidence候補を示す。

既存の経費規程Scenarioでは、検索された文書が本物でも、Modelが額・主体・時点を取り違え得る。
「出典がある」「検索から来た」「主張を辿れる」をそれぞれ検証し、生成Mediaの識別は別の枝として扱う。

### C7.4.1：回答から元文書を特定できるか

Attributionは文書へ結び付ける表示・情報であり、「社内資料より」といった特定不能な表現では追跡できない。
対象がRAG生成の回答かを確認し、検索結果を内部で持つだけでUserへ渡る回答に出典がない経路を見落とさない。

- **正常系:** 回答から今回の元文書を特定できる。複数文書を使うケースも試す。
- **Negative Test:** 参照Dataはあるのに出典を落としたTemplate、Streamingの終了・取消し、Fallback回答を試し、出典の有無を観測する。
- **Evidenceと限界:** 最終Responseと検索記録を対応付ける。原文は全経路で最初のTokenから引用を付ける方式までは指定しない。存在の確認だけで主張の正しさを保証しない。

### C7.4.2：Modelは出典の正本を書き換えられるか

Retrieverが返した文書ID・版・Chunk ID・所在等を、アプリが管理する引用情報として保持する。
Modelが候補IDを選ぶ構成でも、そのIDが今回取得した集合にあるか確認し、表示値はMetadataから構成する。
Modelが作文したURLを後から実在確認するだけでは、由来をMetadataへ置いたことにならない。

- **正常系:** 文書名等の表示値をRetriever由来で構成し、Modelの生成Textに同じ表示値を指定されても置き換わらない。
- **Negative Test:** 存在しないID、他RequestのID、Model生成の偽URLを返させる。取得集合外の参照を採用せず、Metadataの改変経路も調べる。
- **Evidenceと限界:** Requestと検索結果の対応、引用組立ての入力・出力を残す。Metadata自体が攻撃者に編集される問題は別途守る。由来が正しくてもPoisoned文書は残り得る。

### C7.4.3：個々の主張を、版付きの取得Chunkへ辿る

「A部門の承認上限は100万円」という主張なら、同じA部門・時点の条件を含む取得箇所へ辿る。
B部門の規程や古い版の数字が似ているだけでは、A部門の主張の裏付けにはならない。
主張と該当箇所の対応を残すことと、意味上の支持を完全自動判定することは区別する。

- **正常系:** 数値と例外条件を含む各主張から、その回答で使ったChunkと版へ辿れる。
- **Negative Test:** 数値違い、否定の反転、別主体、取得後のIndex更新、Chunk欠落を試す。文書タイトルだけで合格扱いしない。
- **Evidenceと限界:** 主張・Chunk・該当範囲の対応を残す。意味上の支持の評価法と誤りを記録し、特定のNLI製品や完全な真実性を原文要求として追加しない。

### C7.4.4：生成時ではなく、配布するMediaで標識を確かめる

WatermarkはAI生成を示す印。生成直後に存在しても、Resize、再圧縮、形式変換で消えるなら、配布物での識別は示せない。
本文で扱うRAG引用と異なり、ここでは生成画像・音声・動画等の最終成果物が対象になる。

- **正常系:** 採用するMedia形式の最終配布物で、想定方式のWatermarkを検出できる。
- **Negative Test:** 未付与、変換・再圧縮・切抜き後、Watermarkなしの正常Mediaを対にし、見逃しと誤検出を評価する。
- **Evidenceと限界:** 付与器・検出器の版、変換経路、合成Media、検出結果を残す。Watermarkの存在は内容の事実性、特定発行者の認証、非改変の一律の証明ではない。原文の「prove」を無制限の保証へ広げない。

### 更新・運用と保証の限界

Researchは偽引用、Metadataの信頼性、主張と取得箇所の照合、Media変換の問題を補足する。
そこでの特定API、C2PA併用、性能値や法令解説を一律の必須条件にしない。
文書更新・再EmbeddingでChunk IDの意味が変わるなら、過去回答の証拠として版を識別できるようにする。
権限がない利用者へ、出典名やリンクから機密文書の存在を漏らさないことも別途考える。

出典の欠落・照合不能・Watermark検出不能をどう処理するかは用途Policyで決め、
成功した旧版の検証結果を新しい表示Templateや変換器へ流用しない。

**追加演習:** 人事規程のRAGで、正しい文書IDだが別社員区分を根拠にした回答を作る。出典の存在・由来・主張の対応のどこで問題を発見できるか。

## 対話の再構成

1. 問い：本文だけをModelへ渡し、出典名もModelに生成させる。学習者：「Fail」。整理：7.4.2は出典の生成主体を問う。
2. 問い：引用文書が検索結果にあったが、個々の主張と箇所を照合しない。学習者：「7.4.2はPass、7.4.3はFail」。訂正：7.4.3のFailは正しい。7.4.2は出典をアプリがMetadataから作ったならPassと評価できるが、Model生成の出典名が検索結果に存在したと後から確認するだけではPassと断定できない。問いの条件不足を明示した。
3. 所感：「要件は細かいが、Section全体、ひいてはCategoryを線として理解することが重要」。整理：7.4.1～3は検索・出典・支持の線で追える。7.4.4は別の枝。C7全体の各Sectionは直列処理ではなく評価軸。
4. 所感：「7.4はコーディング設計の内容になる」。整理：Controlは何を保証・検証するか、Engineeringは検索結果のData構造・組立て・照合・テストを具体化する。特定実装へControl本文を固定しない。
5. 問い：Watermarkがあれば内容も事実で改変されていないか。学習者：「Fail。内容の事実とは関係ない。そのSystemが出した事実だけ」。訂正：内容の正しさは証明しない。さらにWatermarkだけで特定Systemの発行や非改変まで証明できるとは限らない。AISVS 7.4.4が求める直接の対象はAI生成であることの標識。

## Derived insights・設計レビュー項目

> 出典の存在、出典の由来、主張の裏付けは、三つの異なる問い。

> Sectionを線で理解し、線に乗らない要件は別の枝として明示する。

- 出典表示の値をModelが生成・書換えできるか。
- 検索Metadataの文書ID、版、Chunk IDを回答から辿れるか。
- 出典の文書全体ではなく、主張を支える該当箇所を確認したか。
- Metadata自体の出所・改ざん耐性をどう扱うか。
- AI生成の識別と、発行者認証・非改変・事実性を混同していないか。
