# C3.4 開発・学習の環境から本番へ影響を広げない

## 要件と資料の役割

この文書は講義と対話の学習記録であり、Control本文や製品の適合判定ではない。
NormativeはAISVS正規要件、Researchは脅威と検証の補足、Repository interpretationは現場向けの解釈、Derived insightは対話から得た整理を指す。

| ID | Level | 原文を探す短い英語句 | 日本語での意味 |
|---|---:|---|---|
| `v1.0-C3.4.1` | 1 | AI-specific runtime components | 開発・検証・本番など、環境の境界を越えてAI固有の実行部品を共有しないことを確認する。 |
| `v1.0-C3.4.2` | 2 | isolated from production environments | モデルの学習・微調整環境が本番環境から分離されていることを確認する。 |

英語句は原文全文ではない。正確な英文とLevelは[固定Revisionの正規要件][normative]を参照する。[対応するResearch][research]は実行部品の共有、認証情報、通信経路などの失敗を補足する。特定のクラウド構成や製品は、そのまま必須の適合条件にならない。

## C3の中で何を扱うか

C3.1は投入するモデルの出所と同一性、C3.2は投入前の評価、C3.3は配備と復旧を扱う。C3.4は、開発・学習側の活動が本番へ直接届く経路を扱う。

C3.4.1は環境を跨ぐAI実行部品の共有、C3.4.2は学習・微調整と本番の分離という別の軸である。一方がPassでも、もう一方のPassを自動的には意味しない。

## 具体例と用語

社内Agentは開発用と本番用に分かれている。しかし両者が、本番文書の更新権限を持つ同じMCP Serverを使う。開発Agentが侵害されると、本番用Toolを呼び出せる。

別の例では、モデルの学習Jobを別のクラウドProjectで動かしているが、Jobには本番DBを読む認証情報と、本番のモデル登録先へ書く権限がある。学習環境の設定を変更できる攻撃者は、学習成果物を経由して本番へ影響を与えられる。

- **MCP Server:** AgentへToolやResourceを提供するサービス。この例では本番文書を操作する入口。
- **学習Job:** モデルの学習を実行する処理。モデルだけでなく、認証情報や通信先も持つ。
- **微調整（fine-tuning）:** 既存モデルを追加データなどで学習し、振る舞いを変えること。
- **Project:** クラウド上の管理単位。別名や別Projectであることだけではアクセスの分離を証明しない。
- **昇格:** 検証した成果物を本番利用へ進める操作。学習Job自身の書き込みとは別の権限で行う例を考える。

## 脅威の通り道と守る線

攻撃者が開発Agentや学習Jobを操作できることを前提とする。境界は、開発から本番Toolへ、学習から本番データや配備先へ移る箇所にある。

| 要件 | 守る線 | 主な強制・検証の場所 |
|---|---|---|
| C3.4.1 | 別環境のAgentが、共有したAI実行部品を通じて本番へ到達しない | 環境ごとの実行部品の配備と接続構成、サービス権限 |
| C3.4.2 | 学習側の操作や侵害が、本番へ直接影響を与えない | 学習用IDの権限、通信制御、データ受渡し、本番への昇格経路 |

Repository interpretationとして、権限、通信経路、成果物の反映経路を合わせて見る。独立したクラウドProjectや物理環境は手段の候補であり、名前の分離だけで判定しない。逆に、必要なデータ受渡しをすべて禁止するという意味でもない。

## Pass／Failと保証範囲

| 観察 | 評価 |
|---|---|
| 開発と本番が、本番操作権限を持つ同じMCP Serverを使う | C3.4.1はFail。AI実行部品を環境間で共有している。 |
| 学習環境が分離され、本番の認証情報や接続経路を持たない | 示した範囲でC3.4.2はPass候補。C3.4.1の問題は別に残り得る。 |
| 学習Jobは別Projectだが、本番DBを直接読み、本番モデル登録先へ直接書ける | この構成ではC3.4.2はFail。特に本番へ直接書ける経路が分離を破る。 |
| 本番側で承認済みデータをエクスポートし、学習側はコピーだけを利用する。本番への接続・認証情報を持たず、反映には別の審査と昇格操作が必要 | 受渡しと境界が実際に強制されるならC3.4.2はPass候補。 |

本番由来のデータを使うこと自体は、直ちに分離の失敗にはならない。直接読出しの許否を一般化せず、誰がどの経路で何へ到達できるかを確認する。データ利用の同意、機密性、学習後の安全性、モデルの改ざん検証は別に評価する。
学習・微調整を行わないシステムではC3.4.2の適用範囲を確認する。外部Providerが学習を担当する場合は、自社で実装しないことと、保証を確認しなくてよいことを混同しない。

## 対話の再構成

**問い1:** 開発・本番Agentは別だが、同じ本番操作権限付きMCP Serverを使う。一方、学習環境には本番の認証情報やサービス接続がない。

**学習者の判断:** 「fail」。

**整理:** C3.4.1はFail。C3.4.2は、示した分離条件の範囲でPass候補。二つの軸を分ける。

**問い2:** 学習Jobは別Projectだが、本番DBを直接読めて、本番のモデル登録先へ書き込める。

**学習者の判断:** 「fail」。

**整理:** C3.4.2はFail。Projectを分けても本番へ直接作用できる経路が残る。

**問い3:** 本番で承認したデータをコピーして渡す。学習Jobは本番へ接続できず、成果物の本番反映には別の審査・昇格操作が必要。

**学習者の判断:** 「pass。この要件は権限の分離が目的だから」。

**整理:** 条件が強制されるならPass候補。権限の分離は中心的な手段であり、通信経路や本番へ反映する経路も含めて環境の分離を確かめる。

## 洞察と設計レビューの問い

Derived insight：**環境の名前より、そこから本番へ何ができるかを見る。** この視点は、検証環境、CI、実験用Agentなどにも使える。ただし、各要件の対象範囲はその都度確認する。

- 開発・検証・本番が同じAI実行部品を共有していないか。
- 学習Jobの権限と通信先から、本番への直接経路を辿れるか。
- 学習側のIDで本番への書き込みを試したとき、実際に拒否されるか。
- データ受渡しとモデル昇格は、学習側から勝手に拡大できないか。
- 境界の分離を確認した結果と、データ利用やモデル安全性の評価を分けているか。
