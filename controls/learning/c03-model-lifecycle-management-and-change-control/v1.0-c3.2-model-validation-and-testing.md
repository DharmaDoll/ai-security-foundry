# C3.2 本番で使うモデルの振る舞いを変更ごとに確かめる

## このSectionで学ぶこと

署名されたモデルでも、安全に振る舞うとは限らない。C3.2は、本番で使う前に入力・安全性・出力の試験を行い、量子化や提供者側の変更で実際に使うモデルが変わったときは、以前の合格結果を無条件に引き継がないことを扱う。

この文書は学習用であり、Control本文、製品適合判定、Mappingではない。**Normative**はAISVS正規要件、**Research**は脅威と検証例の補足、**Repository interpretation**は現場向けの解釈、**Derived insight**は対話から得た整理である。

## AISVS v1.0の三つの要件

| ID | Level | 原文を探す短い英語句 | 日本語での意味 |
|---|---:|---|---|
| `v1.0-C3.2.1` | 1 | input validation, safety evaluation, output sanitization | モデルを本番へ出す前に、入力の検証、安全性の評価、出力の無害化について、自動テストを行う。 |
| `v1.0-C3.2.2` | 2 | post-training quantization | 学習後に量子化したモデルは、本番へ出す前に、圧縮後の構成物を元と同じ安全性・アラインメントの試験一式で再評価する。 |
| `v1.0-C3.2.3` | 3 | provider model, version, or routing changes | 提供者側のモデル、版、振り分け先が変わった場合は、使い続ける前にセキュリティを再評価する。 |

英語句は原文全文ではない。正確な英文とLevelは[固定RevisionのAISVS C3正規要件][normative]を参照する。[同RevisionのC3.2 Research][research]は、量子化による安全性の変化、提供者が管理する別名・経路、試験対象と実際の配備対象のずれを補足する。個別ツールや数値閾値をNormativeな一律条件にはしない。

## C3における位置づけと用語

C3.1は「出所と同一性」、C3.2は「振る舞いの投入前評価」、C3.3は「配備中の異常時に安全に戻せるか」を主に扱う。C3.2の評価に合格しても、運用中のすべての入力へ安全に応答する保証はない。反対に、署名検証の成功をC3.2の代わりにはできない。

- **入力検証のテスト:** 想定外または悪意ある入力が、決めた入力境界でどう扱われるかを自動で試すこと。単に通常の質問へ答えられるかを見る試験ではない。
- **安全性評価:** その用途で避けるべき振る舞いを試すこと。例えば不正判定モデルで、特定の入力に対する見逃しを調べる。
- **出力の無害化テスト:** モデルの出力がWeb表示、検索、Toolなど次の処理へ渡るとき、危険な文字列や構造を適切に扱えるかを試すこと。出力内容の真偽だけを測る試験とは異なる。
- **量子化（post-training quantization）:** 学習後に数値表現を小さくし、メモリや計算量を抑える処理。回答精度が近くても、安全性が同一だとは推論できない。
- **アラインメント:** モデルの振る舞いを、想定した安全上の制約や目的へ合わせること。ここでは、その振る舞いが量子化後にも保たれるかを試す。
- **振り分け先（routing）:** 提供者が要求を実際に送るモデルや処理経路。アプリのコードや表示上のモデル名が同じでも、実際の経路は変わり得る。

## 具体例と攻撃の通り道

社内の問い合わせ分類サービスは、不正の疑いがある問い合わせを人へ回す。モデルAは本番投入前に三種類の試験を受けた。運用費を下げるため、チームはモデルAを量子化し、圧縮後のモデルでは回答精度だけを測って投入する。別の経路では、外部のモデル提供者が同じモデル名の背後にある版や振り分け先を変更する。どちらも、以前に試験した対象と、実際に判断する対象がずれる。

```text
試験した版A ──量子化──> 圧縮版A' ──本番判断
      └──提供者が振り分け先変更──> 実際の版B ──本番判断
```

攻撃者は悪意ある問い合わせを送れる。量子化や経路変更を攻撃者が直接行わなくても、古い試験結果を流用していると、新しい版の見逃しや危険な出力を発見できない。信頼境界は、試験済みの構成・経路から、変更後に実際に処理する構成・経路へ移るところにある。

## 守る線と強制する場所

| 要件 | 守る線 | 主な検査・強制の場所 |
|---|---|---|
| C3.2.1 | 入力・安全性・出力のいずれかを未試験のまま本番へ出さない | 本番投入前の自動試験と、その結果を確認するリリース判定 |
| C3.2.2 | 元のモデルの試験結果を、量子化後の別構成物へそのまま流用しない | 圧縮後の構成物を対象とする同じ試験一式の再実行 |
| C3.2.3 | 提供者のモデル・版・経路が変わっても、旧結果だけで使い続けない | 変更の検知、変更後の経路の再評価、継続利用の判定 |

**Repository interpretation:** 試験結果には、対象のモデル構成物、提供者の版・経路、試験条件、合否を結び付ける。Sectionの目的は本番前に定義した安全性評価を通すことだが、個別のC3.2.1原文は三種類の「自動テストを受ける」ことを明示している。具体的な合格閾値や、すべての脆弱性を見つける試験をAISVSが指定したと読まない。試験を実施したという事実と、リスクを許容して本番へ出す判断は分けて記録する。

## Pass／Failと対象範囲

| 観察 | 判定の要点 |
|---|---|
| 本番投入前に、対象の版で入力検証・安全性・出力無害化の自動テストをすべて行った | 評価した範囲でC3.2.1のPass候補。ただし試験の網羅性やモデルの絶対的安全を意味しない。 |
| 入力検証と安全性評価は行ったが、出力無害化の自動テストはない | C3.2.1はFail。三種類のうち一つが欠けている。出力を適切に処理する実装が存在しても、試験の実施とは別である。 |
| 元のモデルは安全性試験に合格した。学習後に量子化し、圧縮版は回答精度だけを測って投入した | C3.2.2はFail。同じ安全性・アラインメントの試験を圧縮後の構成物へ行っていない。 |
| モデルを量子化したが、提供者のモデル・版・振り分け先は変わっていない | C3.2.3は通常N/A。C3.2.2のFailをC3.2.3へ転記しない。 |
| 提供者が同じ名前の背後で実際の版・経路を変更したが、旧結果のまま使い続けた | C3.2.3はFail。アプリのコードが不変でも変更は起きている。 |

C3.2.1は試験の存在と対象を扱うが、発見していない攻撃がないことを証明しない。C3.2.2のNormativeな対象は学習後の量子化であり、Researchに登場する他の圧縮手法へ、この要件の適用を自動的に広げない。C3.2.3は提供者側の変更を扱う。利用者が提供者の内部経路を観測できない場合は、何を把握・固定できるかを明らかにし、無条件のPassを主張しない。

## 対話から残す判断

**問い1:** 元のモデルは安全性試験に合格した。量子化後のモデルでは回答精度だけを測り、本番へ出した。提供者側の変更はない。C3.2.2とC3.2.3はどう評価するか。

**学習者の判断:** 「fail」。

**整理:** C3.2.2はFail。量子化後の構成物へ同じ安全性・アラインメントの試験を行っていない。C3.2.3は提供者側の変更がないのでN/A。対象外はPassではない。

**問い2:** 提供者が、同じモデル名の接続先を新しいモデルへ変更した。アプリのコードは変えず、以前の試験結果を使い続けた。C3.2.3はどう評価するか。

**学習者の判断:** 「Fail」。

**整理:** その通り。見るべきは設定変更の有無ではなく、実際に応答するモデル・経路が変わったかである。

**問い3:** 入力検証と安全性の自動テストは行ったが、モデル出力をWeb画面やToolへ渡す際の無害化は自動テストしていない。C3.2.1はどう評価するか。

**学習者の判断:** 「pass」。

**整理:** C3.2.1はFail。原文は三種類の自動テストを並べて要求している。出力処理の実装が存在することと、その処理を試験したことも別である。この問いによって、入力と安全性の試験だけで「モデル全体の安全性試験済み」と呼んでしまう混同が明確になった。

## このSectionの本質と設計レビューの問い

**Derived insight:** 安全性の試験結果は、抽象的なモデル名ではなく、**実際に使う版・構成物・経路**に紐付く。署名済みでも試験済みとは限らず、元の版で試験済みでも変更後の版が試験済みとは限らない。また、対策が実装されていることと、その対策を自動試験したことは別である。

- 本番で使う構成・経路そのものに三種類の自動テストを行ったか。
- 危険な入力だけでなく、次の処理へ渡る出力の扱いを試したか。
- 学習後に量子化した場合、同じ安全性・アラインメント試験を圧縮版へ再実行したか。
- 提供者の実際のモデル・版・経路の変更を把握できるか。変わった場合、継続利用前に再評価するか。
- 試験結果の対象と、本番で処理した対象を後から突き合わせられるか。
- 試験実施、試験合格、残余リスクの受容を同じ意味として扱っていないか。
