# Engineering Domains

This directory contains the stable technology and trust-boundary categories used to
organize Engineering Patterns. It is not organized by external Framework chapters
or risk-taxonomy identifiers.

## Domains

- [Agents](agents/)
- [Data security](data-security/)
- [Identity and authorization](identity-and-authorization/)
- [LLM](llm/)
- [MCP](mcp/)
- [Memory](memory/)
- [Model and supply chain](model-and-supply-chain/)
- [Observability](observability/)
- [RAG](rag/)
- [Agentic skills](skills/)

Place a Pattern in the Domain where an engineer is most likely to look first. Use
links and separately maintained Mapping assessments for cross-domain relationships;
do not duplicate a Pattern across Domains.
