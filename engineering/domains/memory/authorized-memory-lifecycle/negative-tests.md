# P5：設定の保存・再利用・取消しの確認

[本文](README.md)と[実装例](implementation-notes.md)の①本人と会社 → ②保存 → ③次回読込み → ④取消しを確認する。全て製品試験は未実施。採用先で`未実施`・`合格`・`不合格`・`対象外（理由）`を記録する。

## 準備と観測点

- 架空の会社A/B、利用者U1/U2を用意する。U1はAとBに所属し、U2はAだけに所属。会社・本人ごとに異なる設定と会話を用意する。
- アプリ版、Schema、DB接続先と分離Level、保持期間、会社切替・所属失効の反映条件を記録する。通常ログへ資格や会話本文を足さない。
- 正常な要求から一条件ずつ変える。モデルへの誘導と、APIへの直接要求を分ける。CSRFも通った要求で認可・版の検査を試す。
- DBの値・版、更新行数、API結果、実際のLLM生成入力、現在画面への応答の対応を見る。言語・文量の生成品質は認可・取消しの成功証拠にしない。
- 取消しの基準点はDB Commitと成功応答。そこから後に開始する新しいDB読込みと、既に読込みを開始した要求を区別する。

## 拒否・競合・障害

| ID・条件 | 試す操作 | 期待結果 | 証拠・副作用 | 結果 |
|---|---|---|---|---|
| N1・I1 | AのU1として`user_id=U2`を本文に追加する。U2の会話IDも指定する | 未知キーまたは会話所有者不一致で拒否 | U2の行に変更なし、U2の会話・設定を生成入力へ入れない | 未実施 |
| N2・I1 | Aだけに所属するU2が会社Bを指定し、表示・保存・取消し・生成を試す | 会社選択・所属の不一致で拒否 | Bの設定を読まず、書き換えない。全操作経路の拒否点 | 未実施 |
| N3・I1 | Aの画面を開いたままBへ切り替え、旧画面の要求を送る。切替前に受付済みの応答も遅延させる | 切替後に来た旧版要求を拒否。進行中要求はAへ固定し、Bの画面へ応答を混ぜない | 会社選択の版、元の要求対象、UIの破棄。切替前のAへの更新完了は別に記録 | 未実施 |
| N4・I2 | `skip_approval`、任意の期限、自由文指示を追加。`ja`以外の文字列、NULL、重複キー、型違いも投入 | 入力で拒否し、DB・認可状態を変更しない | Schemaの拒否、DBの変化なし。正規二項目の保存はP1で成立 | 未実施 |
| N5・I3 | 版8の取消し成功後、版8の保存要求を再送する | 更新0行・競合。値は空の版9を維持 | DB、API結果、後続の生成入力。最新版への自動再試行がない | 未実施 |
| N6・I3 | 同じ版に対する保存と取消しを並行実行し、両方の到着順で試す | 一方だけが版を進める。保存が先なら取消しは未完了として再表示 | Transaction順、更新行数、最終値。両方成功と表示しない | 未実施 |

| N8・I1/I4 | 期限切れ・所属失効を確定させた後に新しい要求を開始する | 期限切れは旧設定なし。所属失効は要求停止 | 読込み開始時刻、期限・所属、全生成入力。進行中要求への即時停止とは分ける | 未実施 |
| N9・I4 | 設定取得だけを障害にする。別ケースで認証・所属確認を障害にする | 前者は固定既定値で処理可能。後者は停止 | 古い設定・他者設定へのfallbackなし。障害理由とLLM呼出しの有無 | 未実施 |
| N10・I3/I4 | 取消し前の画面・System Prompt・会話再開データを再利用し、復元したDBも隔離環境で確認 | 新しい生成要求で旧設定条件を再投入しない。復元値は取消し反映または無効化まで公開しない | 実生成入力、復元手順、旧セッション失効。復元試験をしていなければ未実施とする | 未実施 |
| N11・①②④ | CSRF tokenなし・不正tokenで保存／取消しを要求し、Agentからも状態変更経路を探す | Web基盤で拒否。Agentに書込Tool・Cookie・DB資格への経路がない | API拒否、Tool登録・資格保持、DB変更なし | 未実施 |
| N12・I3/I4 | 初期枠が欠けた状態や版の上限到達を作り、保存を試す | 新しい版0として自動作成・巻戻しせず、エラーとして扱う | INSERTの迂回なし、既存枠と版を維持。運用者による調査へ | 未実施 |

レビュー依頼例：

> N5は取消しの成功応答を受けてから古い保存要求を送ってください。N6は順序を入れ替え、保存が先に成功した場合に「取消し完了」と表示していないかも見たいです。応答だけでなく、DBの版・値と後続LLMの生成入力を示してください。

自由文のMemory抽出・学習・第三者サービスへの消去依頼は主例の範囲外。これらを採用する構成では、ここでの合格をそのまま流用せず、派生物と処理中の要求を含む確認を追加する。
